# NSX Migration for VCD v1.5.7 (community build based on 1.4.2.2.H001)

Base: Calsoft-Pvt-Ltd/NSX_V2T_Migration_Tool tag MT_v1.4.2.2.H001 (release.yml build 2024-08-02).
Every changed line is marked with a `PATCH-n` comment. Full diff: v1.5.7-vs-1.4.2.2.H001.diff (attached to the GitHub release). Version history: CHANGELOG.md

| Patch | File(s) | Change | Why |
|---|---|---|---|
| PATCH-1 | core/vcd/vcdOperations.py | Treat a null `ipRanges.values` as an empty list in the target pool update (topology), source pool cleanup and target pool rollback | VCD returns `null` for empty pools; the tool crashed with AttributeError/TypeError |
| PATCH-1b | core/vcd/vcdOperations.py (`_updateTargetExternalNetworkPool`) | Add only IPs not already in the target pool, one single-IP range each | Allows a target /30 pool to be pre-seeded with the edge's own IP without creating a duplicate range |
| PATCH-2 | core/vcd/vcdValidations.py (`staticRouteCheck`, LB vNIC map), core/vcd/vcdConfigureEdgeGatewayServices.py (LB vNIC map) | Iterate every address group on a vNIC instead of assuming exactly one | Mixed public+private uplinks have two address groups; static route check crashed, LB VIP mapping silently missed IPs |
| PATCH-4 | core/vcd/vcdValidations.py (edge uplink and shared direct network validation) | Return the intended error when the `-v2t` network does not exist | GitHub issues #4 and #7: "list index out of range" instead of a readable message |
| PATCH-5 | commonUtils/certUtils.py | Raw RSA decrypt via `pow()` and explicit `AES.MODE_ECB` | Works with pycryptodome (pycrypto does not build on Windows / Python 3.8); mathematically identical to pycrypto behaviour |
| PATCH-7 | commonUtils/passwordUtils.py | On Windows the password file's master key is wrapped with DPAPI (bound to the Windows user account and machine); on Linux the file is written with mode 600. File format unchanged; files from older builds can still be read | The original file stores the decryption key in clear text next to the encrypted passwords |
| PATCH-8 | core/vcd/vcdValidations.py (`validateVappLeases`, called in vApp validations), vcdNSXMigratorV2TAssessment.py | New check of vApp runtime and storage leases. Precheck/migration: expired storage lease fails validation; leases expiring within 72 hours are logged as warnings. Assessment: new report column 'vApp lease expired or expiring soon' (Can be mitigated) | The tool did not check leases; an expired vApp makes movevapp fail mid-window and a lease expiring during the window powers off or suspends the vApp |
| PATCH-9 | core/vcd/vcdConfigureEdgeGatewayServices.py (`filterApplicationPortProfiles`, `_searchApplicationPortProfile` + helpers) | Application port profiles are found or reused before creating: tenant profiles are indexed by name (including multi-port ones); an existing profile with the same name and definition is reused; if the name is taken by a different definition, `CUSTOM-<proto>-<port>-<8 chars of target Org VDC id>` is created; if VCD refuses creation, the profile is looked up by name and reused when it matches. Only profiles usable in the target Org VDC context (same NSX-T Manager) are reused. Names longer than VCD allows are shortened to the start of the port list plus a stable hash | Upstream issue #2: 'Application Port Profile ... already exists' when a second Org VDC of the same organization is migrated in a later run, after rollback and re-migration (rollback does not delete created profiles), or when a tenant profile uses the same name |
| PATCH-10 | core/vcd/vcdValidations.py, core/vcd/vcdOperations.py, core/vcd/vcdConfigureEdgeGatewayServices.py, vcdNSXMigrator.py, rollback.py | **Opt-in, per Org VDC.** `TransportSubnets` (CIDR list): the uplink subnet holding an edge's default gateway is treated as transport when it lies in these ranges - not required on the provider gateway, not configured on the Tier-1, not added to pools or floating IPs; kept as before when NAT, IPsec or load balancer configuration uses its addresses; transport-only edges are connected to the Tier-0 without uplink IPs. `DmzStaticRoutes` (CIDR list): routed networks inside these blocks get a static route on the provider Tier-0/VRF to the tenant Tier-1 during services (removed in rollback; warns if the Tier-0 does not redistribute static routes). Always on: fix for the precheck crash on policy-based IPsec without NAT rules. Without the two keys the tool behaves exactly as before | Transport-free target design: tenants reach the world only via Tier-1 -> Tier-0 -> BGP |
| PATCH-11 | vcdNSXMigrator.py, core/vcd/vcdOperations.py, rollback.py, vcdNSXMigratorCleanup.py, commonUtils/logConf.py | New `--movecatalog` mode (run after movevapp): catalog items stored on the source Org VDC are moved to `<catalog>-v2t` catalogs on the target (created when missing), using cleanup's catalog logic without deleting/renaming. The pairs are recorded in metadata. `--rollback` moves all items of those `-v2t` catalogs back to the source catalogs as its last step before the target networks are deleted (after vApps, disks, edge/network switch-back, DFW, LB and DC group rollback), and deletes `-v2t` catalogs it created. `--cleanup` deletes the old source catalogs and drops the `-v2t` suffix (a source catalog that still holds items of other Org VDCs is kept). Without `--movecatalog` nothing changes. v1.5.5 fixes before release: `@isSessionExpired` restored on `moveCatalogItem` (the inserted PATCH-11 block had taken it over, so long catalog moves in movecatalog, rollback and cleanup could run into an expired session); `finalizeCatalogMoves` saves the finished list to the target Org VDC metadata; unused variable removed. Known limit: rollback does not change the network references of vApp templates created on the target, see README Known limitations | Catalogs usable on the target right after the migration instead of only after cleanup |
| PATCH-12 | core/vcd/vcdValidations.py (`getEdgeGatewayNoSnatStaticRoute`), core/vcd/vcdOperations.py (`configureDmzStaticRoutes`) | (a) Subnets on the uplink that carries the default route are no longer treated as non-default uplinks: their SNAT rules keep destination `any`, and static routes through that uplink no longer create NO_SNAT rules. Uplinks without the default route (for example private service uplinks) behave as before. (b) `configureDmzStaticRoutes` finds the DMZ networks among the target Org VDC networks connected to the Tier-1, and logs a warning when `DmzStaticRoutes` is set but nothing matches | (a) NSX-V applies an SNAT rule to all traffic leaving the vNIC; the tool limited SNAT on a public subnet next to the transport subnet to destination <public subnet>, so outbound internet traffic was not translated. (b) By the time the routes were created, services had made the source routed networks ISOLATED, so no DMZ network was found and no route was created, without any message |
| PATCH-13 | core/vcd/vcdValidations.py (`dropTier0UplinksWithoutTransport`), core/vcd/vcdConfigureEdgeGatewayServices.py (`configureTargetNAT`) | Only when `TransportSubnets` dropped the edge's transport subnet: uplink subnets recorded as Tier-0 connected (`isT0Connected`) are removed from the non-default uplink list before the NAT rules are built, so their SNAT rules keep the source destination. Uplink subnets that become Tier-1 service interfaces are unchanged; with the transport subnet kept, or without `TransportSubnets`, nothing changes. Logged per subnet | On NSX-V such a subnet was not the default route, so the tool limited its SNAT rules to destination <that subnet>. After a transport-free migration all traffic leaves through the Tier-0, and the copied restriction stopped outbound translation |

Not included: patch 3 (containment for legacy pools) - not needed if IP Spaces is used.

src/release.yml reports Build v1.5.7 (v1.5 plus PATCH-7 to PATCH-13). The build version is only shown on the console and in assessment reports; it is not stored in migration metadata.

Build changes: pyinstaller-hooks-contrib pinned to 2021.3 (compatible with PyInstaller 4.5.1); spec hidden imports cleaned up; Windows requirements use pycryptodome; build_windows.bat added.
